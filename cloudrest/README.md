# 栖云

> 写下你的场景，它自己挑体裁。

三段式的工作台：左边是它读你的场景后**取到的那一刻、用的典故与修辞、以及一篇自评**；
中间是诗；右边写你的要求——**成诗之后还可以继续提要求，它会照你的话接着改**。

## 它是怎么写的

一次「落笔」走三步：

1. **择体**（`/api/choose`）：先读场景，从 30 种已核验体裁（4 种近体诗 + 26 个词牌）里挑一个最合式的，并说明理由——
   为什么用短调、为什么用仄韵、为什么这里的声情要参差。同时从 164 条典故里挑一条真正相扣的。
   理由显示在左栏。
2. **成诗**（`/api/compose`）：把该体裁的**句式骨架、逐句平仄、韵位**一并交给模型，
   写完立刻校律；不合就带着**具体到某字某句的错误**重写，最多 4 遍；若它自己指出的是套语病，还会在「润色」轮再改一稿。
3. **润色**（自评 → 重写）：成稿之后再当一次**苛刻的评家**，只挑真正的问题，然后据此重写一稿。
   左栏会把「它对自己上一稿的批评」和上一稿一并给你看，好让你对照它到底改了什么。

**取舍**：若它自己指出的病很重（套语、拼贴、与场景无关），宁可让平仄多几处出入，也要换掉那一稿——
一首贴满通用配方的诗，即使平仄全合，也不是好诗。

右边可以随时提要求（「写得再冷一些」「不要写离别」「把重点放在那盏灯上」），
或直接点词牌指定体裁；成诗后点「照此润色」，它会在**保持合律**的前提下重写，并说明这一稿改了什么。

### 借谁的笔法

右栏可以选一位诗人（王维、李白、杜甫、白居易、李商隐、李清照、陆游、辛弃疾、苏轼、纳兰性德、毛泽东、鲁迅），
栖云就用他的眼睛与句法写你眼前的场景。

**仿其笔法，不袭其句**——这是硬底线。`server/poets.mjs` 里给模型的是这位诗人
「看世界的方式、句法习惯、意象取材、最容易学坏的地方」，并明确要求：
任何一句读来让人想到他的某句名作，即为失败。

### 用典

`server/allusions.mjs` 收录 **164 条**典故（先秦至唐 64 条、宋至近现代 100 条），
由两个子代理**逐条网络检索核实**出处，精确到篇名与卷次。

不是把整库塞给模型——那会淹没它。做法是分两步：
1. 择体那一步先按场景情感筛出候选池（医院 → 悲慨，古塔 → 咏史，梦境 → 哲思，站台 → 送别），
   让模型自己挑一条真正相扣的；
2. 成诗时只把挑中的那条给它，并明令**最多用一处，也可以一处都不用**，
   用错了比不用更糟。

实测两例：
- 「登古塔望废城」自己挑了张养浩《山坡羊·潼关怀古》，写出「莫言此地曾歌舞，数点归云似旧旌」——
  化用其意，不袭其句，平仄出入 0。
- 「梦见自己变成鸟」自己挑了**庄周梦蝶**，写出「枕上忽惊羽翼／只疑身是轻翮」——
  托出真假一身之迷惘，正是《齐物论》那层意思。

两批数据的存疑条目都写进了各自的 `avoid` 字段与 `.research/allusions-*-notes.md`，不掩饰。
例如于谦《石灰吟》归属争议、张骞乘槎系后起附会、湘妃竹有《博物志》与《述异记》两说。

「或自己填词牌」那一栏可以填任意词牌（如水调歌头、减字木兰花）。**我没有这些词牌的核验词谱**，
所以走的不是校律，而是另一条路：让它先在 `<meter>` 里声明该词牌的句式，再由服务端核对
「正文是否与它自述的句式逐句一致」，并把「未核验词谱、平仄与押韵未经校对」如实标在页面上。
要严格校律，请从上面已核验的 26 调里点选。

## 校律的两级

- **必改**（会退回重写）：句数、每句字数、分片与句式骨架不符。这些来自词谱正文，可严格判定。
- **宜改**（只作说明与重写参考）：平仄出入超过 3 处、**出现现代语汇或白话**、
  **律诗中间两联的对仗硬伤**（对应位置重复用字、两句同字收尾）。
- **提示**：韵脚同韵。近体诗按《平水韵》严格判定；词的换韵结构复杂
  （尤其《相见欢》《虞美人》《定风波》这类换韵且原文未另起一行的），故只作提示，
  不因它把一首好诗硬判为不合格。

### 两道防误判

1. **白话词表以「古人不误伤」为底线**。曾把「寂寞」（苏轼「寂寞沙洲冷」）、「伤心」
   （李白「寒山一带伤心碧」）、「总是」（晏殊「凭阑总是消魂处」）、句末的「了」
   （李煜「人间万事何时了」）误判为白话——全部修掉，单字一律不裸列。
   `.research/test-language.mjs` 用 21 首钦谱例词 + 四首名作守住零误报。
2. **长调按句式重新切行**。长调最常见的失败不是写错字，而是把两句并成一行
   （《水调歌头》19 句写成 8 句）。既然句式已由模型声明，切行就是机械的事：
   先首尾相接再按句式切开，切完逐句吻合才算数，切不动才判错。

### 正文清洁（曾经漏过的 bug）

模型有时会把不该进正文的东西写进 `<body>`，几次都真的漏到了页面上，现已都堵住：

1. **把平仄谱抄进正文**。七律那一稿 `<body>` 里先写了 8 行「仄仄平平仄仄」再写 8 句诗，
   渲染出 16 行。现在整行识别为谱的一律剔掉，剔掉后句数不对即触发重写。
2. **把提示词原文抄进正文**。有一稿把「里**只许写字**绝不可把上面给你的平仄谱…」当成诗句写了出来。
   现在正文出现说明性用语、或单行超过 12 字，整行丢弃并重写。
3. **末句字数不足仍被渲染**。有一稿七律末句只有 6 个字「九州同辙即能」。
   根因是**重写用尽后我仍把最差的稿渲染了出来**。现在加了「按句式机械切行」：
   句式是确定的，把两句并成一行、或某行多字，都能按该句应有字数切正；
   切不动（真的少字）则继续重写，绝不输出坏句。
4. **自批在批评另一首诗**。润色换稿成功后，自批文本仍针对旧稿，等于让用户看一段评别人诗的评语。
   现在自批与它所批评的那一稿一并存下、一并展示。

### 一道数据防线

抽取词谱时曾**取错了「格」**：因 id 映射错误，《望海潮》取回的是《鹤冲天》、
《八声甘州》取回的是《双雁儿》、《水龙吟》取回的是《雪明鳷鹊夜》、
《永遇乐》取回的是《剪牡丹》、《扬州慢》取回的是《琐窗寒》——
而抽取器自带的「例词与词谱自洽」检查**完全无法发现**这种错，因为错的那一整页也是自洽的。

现在多了一道**独立核对**：每个词牌的字数须与通行正体相符，否则一律拒收。
这 5 个词牌就是这样被挡在表外的，宁缺勿错。`.research/test-tune-lengths.mjs` 守住这条。

## 诗心准则

写在 `server/prompt.mjs`，是这个项目真正的核心。它针对旧体诗最常见的**四病**而设：

| 病 | 症状 | 治法 |
| --- | --- | --- |
| 意浮 | 立意平平，换个人也写得出来 | 落笔前先回答「这一刻最让我动心的是什么」；同题之作若别人能一字不改，即为失败 |
| 象裂 | 意象各说各话，彼此咬合不上 | 用王夫之「情景名为二，而实不可离」作尺：情抽掉景还站得住吗？景换成同类词情变了吗？ |
| 典浮 | 用典与境无关，为对仗而填 | 顺序只能是「我有此情 → 想起那个典」，不能反过来；真没有接口就宁可不用 |
| 旁观 | 只作观看者，不动心，不入局 | 写你真正被打动的那一下，不写「通用的感慨」 |

此外还有几条硬约束：

- **只许旧体诗词的语言**：列了明确的禁用词表（时间、心情、工作、手机、的了吗呢……），
  场景里出现现代词，必须化成古人的说法（「加班到十一点」→ 夜归、灯火、更深）。
- **不许用没有实感的抽象词充数**：孤独、寂寞、惆怅——那是**说**情绪，不是**写**情绪。
  情绪要靠物象去打：写他反复摩挲那只杯子，比写「孤独」重十倍。
- **尾联最要紧**：以景结情 / 以翻转收 / 以一句狠话收，三者取一；最忌「半襟」「些许」这类温吞说法。
- **一律简体**：模型偶尔会飘到繁体去（实测出现过「隔岸樓高燈自密」夹在简体里），
  繁简混用是一眼可见的破绽。`server/script.mjs` 收 740 个常见繁体字，命中即判 **必改**、退回重写。
  这一档是**精确**判定，所以判 error；而白话词那一档靠词表，边界模糊，只判 warn。
- **不仿写**：任何一句读来让人想起某首名作，即为失败。

改这个文件就能改它的脾气。

1. **已核验词牌 26 种**。原先只有 21 种，经补抓已加入你点名的
   《水调歌头》《念奴娇》《满江红》《沁园春》《雨霖铃》。
   另有 5 种（《望海潮》《八声甘州》《水龙吟》《永遇乐》《扬州慢》）**因我取错了格而被拒收**——

   宁缺勿错。这些词牌仍可自填，但走「声明句式 + 核对是否自洽」，**平仄与押韵未经校对**，页面上会如实标注。
2. **平仄做不到 100%**。常见一次成稿即 0 出入，但偶尔仍会有几处不齊。
   尤其在「润色」那一轮：若它自己指出的是套语病，我宁可让平仄多几处出入也要换掉那一稿。
   页面会如实标出还剩几处。
3. **律诗对仗只抓可判定的硬伤**：对应位置重复用字、两句同字收尾。
   「词性是否相对」需要词性知识，无法机械判定，故不做断言。
4. **词林正韵有 9 个「半」韵目覆盖偏少**（十灰、九佳、十三元等），
   韵书只用来源明列之字，不猜哪一半归哪部，故个别韵部字表偏窄。
5. **多音字判定偏宽松**：按「存在任一共同韵部」算，个别该出韵的可能放过。
6. **繁体字检测是「常见字全覆盖、生僻字可能漏」**。`server/script.mjs` 收了 740 个繁体字，
   表在载入时逐项自检（二字一对、繁简不同字），并由 `.test/script-test.mjs` 守着
   「四首名作零误报」（完整版另在 `qiyun/.research/test-script.mjs`，跑 31 首例词）。
   但**召回没有可靠度量**：本地语料（sou-yun / 诗词家园抓回的那批）在抽取阶段就已转成简体，
   没有一份繁体参照可以用来算漏判率。所以只敢说「常用繁体字基本不漏」。
   ——另外，凡是简体里**也**通用的字（著、藉、乾、徵、面、里、台、只、并、后、发、干、
   尽、复、系、松、谷、划、咸、恶、丑、采、布、才、尝、卷、舍、制、志、注、表、别、冲、
   梁、檐、峰、群、污、泛、席、杯、吃、挂、玩、昆、岳、溪、床……）一律不收，
   宁可漏判也不误伤真诗；这一条由测试里的「高危字逐个确认表里没有」钉住。
7. **诗质仍在爬坡**。它已经能自己批出「意象悬浮」「立意浮了」这类真问题，
   但改成什么样，终究受模型本身的天赋所限，偶尔仍会写出套语。
   这一层我没有更好的办法，只能靠准则、自评轮与你的具体指令一次次逼近。
8. **账号系统是「能用且诚实」，不是「企业级」**：邮箱不验证（没有发信服务），
   忘记密码没有自助找回，口令散列迭代次数偏低（受 Workers 免费版 10ms CPU 限制），
   会话票据无法单独吊销。逐条理由与取舍写在 [ACCOUNTS.md](ACCOUNTS.md) 里。
9. **付费无法自动识别**。个人微信收款码没有任何回调，所以只有「兑换码」与
   「付款认领 + 站长确认」两条人工路径。要全自动必须有微信支付商户号，
   而商户号要有营业执照。详见 [ACCOUNTS.md](ACCOUNTS.md)。
