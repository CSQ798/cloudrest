# 栖云 · 账号、额度与付费

规则（按你定的）：

| 身份 | 能写几首 |
| --- | --- |
| 没登录、也没密钥 | 一首都不给（会提示去注册，或点开页脚的「小启」） |
| 注册用户 | 免费 **5** 次 |
| 在工具栏输入密钥 | **不限次**（密钥默认 `798798`） |
| 次数用完 | 提示去看页脚那个「小启」，那里有站长邮箱 |

> **「买额度」已经撤掉了。** 站长要的是「免费 5 次 + 想多用就来信」，
> 所以页面上不再有付款入口，服务端那句 402 也不再提钱。
> 但底下的机制**都还在、都没删**：`/api/redeem`（兑换码）、`/api/claim`（付款认领）、
> `admin.html`（管理页）、以及 D1 里的 `credits` / `claims` / `redeem_codes` 三张表。
> 将来想启用，把界面接回去就行，后端一行都不用改。
> 下面第二、三节仍然保留，是为了那份「为什么个人收款码无法自动识别」的分析 ——
> 你哪天真的想收费，那是必须先看的结论。

## 一、先说最要紧的那个问题：能不能自动识别扫码付款

**不能。** 我认真找过了，你把个人微信收款码给我，服务器这边是拿不到任何信号的：

| 路子 | 能不能自动到账 | 为什么 |
| --- | --- | --- |
| 个人收款码（你给的那张） | ❌ | 微信**没有任何回调**。钱进了你的零钱，但没有任何东西会通知服务器「某某付了 1 元」。这是产品设计如此，不是接口藏起来了。 |
| 微信支付商户号 + APIv3 + 支付回调 | ✅ | 但要**营业执照**（企业或个体工商户）才能开通商户号。个人开不了，这条路现在走不通。 |
| 支付宝当面付 | ✅ | 同样要营业执照。 |
| 第三方「码支付 / 易支付」平台 | ⚠️ | 它们靠挂机监听或转接实现，多数在灰色地带，随时跑路、可能封号，还可能把你的收款码交给别人。**不建议**。 |
| 安卓手机监听微信收款通知 | ⚠️ 勉强算 ✅ | 装一个常开的安卓 App，用系统的通知读取权限抓「微信支付收款 1.00 元」这条通知，再 POST 到你的服务器。技术上真能跑通，但要一台**一直开着、联网、不锁屏清理**的安卓机，微信改通知格式就失效，而且把通知读取权限交给第三方 App 本身有风险。 |
| **人工确认** | ✅（要你动一下手） | 见下。 |

所以本站做了两条**不需要营业执照、也不需要第三方平台**的路。都是我实测过的（`.test/account-test.mjs` 和 `.test/e2e-accounts.mjs` 分别从函数层与 HTTP 层各跑一遍）：

### 路一：兑换码（推荐，最省事）

你在管理页点一下「生成 10 个码」，把码存下来。
有人付了 1 元，你发一个码给他，他自己在网页上填，**立刻到账**。
你的事：复制粘贴一次。没有待办堆积。

### 路二：付款认领（用户自助提交，你点一下确认）

用户在「买额度」面板里点「我已支付，提交」，填一句备注（付款时间、单号后几位）。
你在 `/admin.html` 里对着手机账单核一下，点「通过」，额度立刻到账。

两条可以同时开着。都**不需要**你去改代码。

> 说句实在话：这条路的天花板是「你得动手」。真要全自动，前提是搞到营业执照开商户号，
> 那时候我可以给你接微信支付的 Native 下单 + 回调，做到付款即到账。
> 现在这个阶段，人工确认是唯一诚实可行的方案。

## 二、部署时要配的三样东西

都在 Cloudflare 控制台，用不着命令行。

### 1. D1 数据库（额度的存放处）

额度必须**跨请求、跨实例**算数，Workers 是无状态的，所以必须落库。

> Storage & Databases → **D1** → Create → 名字填 `qiyun`
> 然后 Workers & Pages → `cloudrest` → Settings → **Functions** → D1 database bindings
> → 变量名必须是 **`DB`**（代码里认的就是这个名字）→ 选刚建的库

**表结构不用你操心。** 站点第一次用到数据库时会自己把表建好（`server/schema.mjs` 里那几条
`CREATE TABLE IF NOT EXISTS`，幂等，建过就不再建）。所以整套配置只剩两步：建库、绑上。

> 想手工执行也可以，但没必要：
> - 控制台：D1 → 这个库 → Console，把 `migrations/0001_init.sql` 整段粘进去执行；
> - 命令行：`npx wrangler d1 execute <库名> --remote --file=./migrations/0001_init.sql`
>
> 那份 `.sql` 只是 `server/schema.mjs` 的抄本，由 `.test/schema-test.mjs` 逐句比对，
> 两边说法一旦不一致就会红。

**没绑定 D1 会怎样**：免费那条路**直接关掉**。
具体说：没登录、没密钥的人来点「落笔」，会收到 503 与一句说明
（「服务端还没有配置额度，为避免失控，免费次数暂时关闭」）；
**有密钥的人照常能用**，所以你（站长）自己进得去。
`/api/health` 里写着 `accounts: false`，页面顶部会挂一条红色告警条，
登录按钮**仍然显示**（点开会看到服务端给的原因，而不是找不到入口）。

> 这一条我改过一次，值得记下来：第一版是「没绑库就一律放行」，
> 想法是「别让站点因为没配好就用不了」。结果是——站长看到「额度未启用」
> 却以为限额开着，而实际上**所有人都不限次**。
> 静默放行比明说不设闸更糟，因为它会让人以为自己已经守住了。
> 现在改成拦住，并说清缺什么。

### 2. `SESSION_SECRET`（登录状态的签名密钥）

> Settings → Variables and Secrets → Production → Add → 类型 **Secret**
> 名称 `SESSION_SECRET`，值随便一串长随机字符（比如 40 位）

**没设会怎样**：注册与登录返回 503 并说明原因；密钥那条路不受影响。
（为什么不给个默认值：默认值等于把「伪造登录状态」的方法写在源码里，谁都能登进任何账号。）

### 3. `ACCESS_KEY`（站点密钥）

不设就是默认的 `798798`。想换就在同一个地方加一条 `ACCESS_KEY`。

> ⚠ **`798798` 是 6 位数字，一共 100 万种。** 不限速的话脚本几分钟就能穷举完。
> 所以我加了按 IP 的限速：10 分钟内最多试 10 次，超了返回 429。
> 这样穷举一遍要**几十年**。但仍建议你换成一串长随机字符——
> 密钥是「不限次」的凭据，值越低越不该用短数字。

## 三、这套东西的安全边界（不掩饰）

| 项 | 现状 | 说明 |
| --- | --- | --- |
| 邮箱验证 | **没有** | 本站没有发信服务（要 Resend/SendGrid 之类的外部账号）。所以邮箱**只是账号名**，不证明归属。 |
| 忘记密码 | **没有自助找回** | 同上，没有发信渠道。只能由站长在 D1 控制台里处理。 |
| 口令散列 | PBKDF2-SHA256，**25,000 次** | 这个数字偏低，是**有意的妥协**：Workers 免费版每次请求只有 10ms CPU，本机实测 25,000 次≈2.4ms、100,000 次≈9.1ms（贴着上限）。想要更强就得升付费版或把散列挪到独立服务。写在 `server/account.mjs` 顶部。 |
| 会话 | HMAC 签名的自包含票据，HttpOnly + SameSite=Lax | 好处是不查库；代价是**没法单独吊销某一个会话**，退出登录只是让浏览器删 Cookie。要全吊销就换 `SESSION_SECRET`。 |
| 限速 | 按 IP 的滑动窗口 | 密钥尝试 10 次/10 分钟；注册登录 20 次/10 分钟。存在 D1 里，不是内存（内存限速跨实例就失效）。 |
| 数据 | 邮箱、口令散列、用量、认领记录 | 都在你自己的 D1 库里，不经过任何第三方。 |
| 管理页 | 同一个站点密钥当口令 | 口令只存在你浏览器的 localStorage，请求时走 `X-Access-Key` 头，**不进网址、不进 Cookie、不进访问日志**。但 `/admin.html` 本身是公开可访问的页面（只是没口令打不开接口）。 |

## 四、搬到微信小程序？——**不建议，而且它解决不了付款问题**

先说结论：**小程序不会让付款变简单，反而更难。** 三条硬门槛：

1. **个人主体的小程序根本用不了微信支付。**
   要在小程序里收款，必须有**微信支付商户号**，而商户号要**营业执照**。
   也就是说，你在网页上遇到的那堵墙，小程序里一动不动地还在，还更硬。

2. **小程序要求请求域名已 ICP 备案，且必须是 HTTPS。**
   `cloudrest.pages.dev` 不可能备案（备案要有中国大陆的主体与境内接入商）。
   所以你至少还要：买域名 → 在国内服务商备案（几周）→ 把服务迁到境内主机或走国内接入。
   这一套下来，现在「一个 zip 拖进控制台就能用」的优势全没了。

3. **要有小程序账号并实名。**
   注册小程序、主体认证、装微信开发者工具、上传审核（每次改动都要重新审）。
   个人主体能注册小程序，但**不能**开通支付、不能做经营性内容。

另外还有个绕不开的合规现实：这类「AI 生成内容 + 收费」的小程序，审核时通常需要
《互联网信息服务算法备案》或至少明确的内容安全方案；个人主体很难过。
网页版至少不需要过审。

**如果你还是要做**，需要你准备的是：

| 你要做的 | 说明 |
| --- | --- |
| 营业执照（个体户也行） | 开微信支付商户号的**前提** |
| 小程序账号 + 主体认证 | 个人主体可注册，但用不了支付 |
| 一个能备案的域名 | 且要备案通过，才能配进小程序的 request 合法域名 |
| 境内服务器（或用云开发的云函数） | 备案要求接入境内；Cloudflare 的 pages.dev / workers.dev 都不行 |
| 内容安全方案 | 小程序对 UGC/AIGC 有审核要求，文本要过 `msgSecCheck` |
| 把后端迁过去 | 现在是 Cloudflare 专用的（D1/Workers 运行时），迁到微信云开发要重写数据层与调用层，我这边估算是把 `server/store.mjs` 换成云数据库、把 SSE 改成轮询或 WebSocket 的区别 |

**我的建议**：先把网页版跑起来收钱（路一的兑换码几乎零成本），
等你确认真有人愿意付 1 元，再去办执照、再谈小程序迁移。
现在花几周去备案 + 认证，换来的能力并不比网页版多——
反正到那一步你还是需要营业执照。

## 六、页脚那个「小启」

账号页（/account.html）上有一节「小启」（`public/index.html` 里的 `<details class="quiet">`，
原生元素，没有一行 JS）：

> 小站一人之力，每写一首都要向 AI 付费，故难对所有人无限开放。
> 想常用，来信说一句你打算写什么、为何想写 —— **1876148307@qq.com**，
> 我多半愿意分你一把钥匙。

它承担一件事：把「想多用几次」的人引到你的邮箱。
所以服务端几句拒绝的提示（401 / 402 / 503）都不再说「在工具栏输入密钥」——
密钥是站长发的，访客手上没有，说那句等于让人干瞪眼。现在一律指向那个「小启」。

以前这里是一整段常驻的文字，占了页脚一大块；站长嫌它又长又挡地方，
所以压成两句，并收进标签里。

## 七、我怎么验的

```bash
node .test/account-test.mjs      # 函数层：同一套用例跑两遍（内存 + 真 SQLite 跑 D1 的 SQL）
node .test/e2e-accounts.mjs <网址>  # HTTP 层：注册→密钥→成诗→用光→兑换→认领→确认，真 Cookie
```

`account-test.mjs` 特意跑两遍的原因：D1 版的关键逻辑全在
`UPDATE users SET free_used = free_used + 1 WHERE id = ? AND free_used < 5`
加 affected rows 判断上，**不真跑一次 SQL 就不算验过**。
脚本用 Node 22.5+ 的 `node:sqlite` 起一个真的 SQLite，把同一批 SQL 喂进去，
两个后端必须给出一模一样的结论。其中一个用例是并发：余额只剩 1 时同时发 5 个扣减，
必须只成功 1 个 —— 这条只有在真 SQL 上才有意义。
